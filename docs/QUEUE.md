### T-33 · 单用户登录门禁

**目标**：改 SPEC「运行形态」「多用户架构」「users 表」与 API：公网部署必须登录才能改数据。替换 `DEFAULT_USER_ID` 直通中间件；不开放注册。

**范围边界**
- 允许修改：docs/SPEC.md 运行形态 / 多用户架构 / users / API；internal/auth 中间件实现；users 表字段；login/logout/me 接口；前端登录页与 401 跳转；docker-compose.yml / README 环境变量
- 禁止修改：业务四表结构；handler / service 业务计算（只换认证来源）
- 禁止操作：不得开放注册接口；不得把密码明文写入仓库或日志

**关键约束**
1. 不提供注册。账号由启动时环境变量写入：`INITIAL_USERNAME`（缺省 `admin`）+ `INITIAL_PASSWORD`（必填，空则 api 拒绝启动）。仅当该用户尚无 password_hash 时写入，已有密码则忽略环境变量。
2. `public.users` 增加 `username TEXT NOT NULL UNIQUE`、`password_hash TEXT NOT NULL DEFAULT ''`；`name` 仍作显示名。
3. `POST /api/login` body `{username, password}`；成功 Set-Cookie HttpOnly、SameSite=Lax、Path=/；失败 401。`POST /api/logout` 清 Cookie。`GET /api/me` 返回当前用户（未登录 401）。
4. 除 login 外全部 `/api/*` 走 Cookie 鉴权；未登录 401。前端未登录进登录页，业务页不可用。导航提供退出。
5. 去掉 Compose 场景下的免登录直通。`DEFAULT_USER_ID` 不再作为鉴权旁路（可保留仅用于首次建 schema 的用户 id，缺省 1）。密码哈希用 bcrypt。

**验收标准（逐条自检并汇报）**
1. 未带 Cookie 访问 `/api/strategies` 返回 401；登录后可读写。
2. 错误密码 401；退出后再访问 401。
3. 仓库与日志无明文密码；无注册入口。
4. `docker compose` 文档写明 `INITIAL_PASSWORD`。
5. 暗色登录页正常。

**完成后**：停止等待验收。清理只在人工「T-33 验收通过」后按 WORKFLOW 执行。

### T-34 · 交易日历完整版

**目标**：改 SPEC「为未来预留」交易日历与日期体系：落地 A 股交易日（周末 + 法定节假日），前后端所有「上一交易日 / 近 N 交易日 / 本月」与日期选择器一次性切到该日历。录入默认日期仍为当天。

**范围边界**
- 允许修改：docs/SPEC.md 交易日历与相关派生规则；日历数据与 API；frontend `src/lib/date.ts`、DatePicker、录入/图表/复盘里依赖交易日的逻辑
- 禁止修改：strategy_metrics / review_notes 存库字段；登录与认证
- 禁止操作：不得把录入默认日期改成上一交易日；不得只做周末、把节假日留到后续任务

**关键约束**
1. 日历覆盖至少 2020-01-01～2028-12-31 的上交所/深交所交易日（周末休市 + 国务院放假安排对应的 A 股休市，含调休上班日为交易日）。数据随仓库发布，启动写入（或只读内置表），不依赖外网。
2. `GET /api/calendar?from=&to=` 返回 `{date, is_trading_day}` 列表（或等价：只返回交易日数组，前端可判定）。节假日与周末均为非交易日。
3. 前端 `isTradingDay` / `previousTradingDay` / `lastNTradingDays` / `thisMonthTradingRange` 全部改走该日历；禁止再按「周一到周五」判断。
4. DatePicker（录入与筛选）改为月历网格：可跳转年/月（下拉或输入，禁止只能一页页翻）；可直接输入 YYYY-MM-DD；非交易日灰显且录入模式不可选；已有指标的日期打点。筛选模式仍可只列出有数据的日期，但月历跳转能力同样具备。
5. 录入弹窗默认日期 = 打开时的当天（自然日）。图表「近 20 交易日 / 本月」按新日历计算。

**验收标准（逐条自检并汇报）**
1. 2026-10-01、2026-01-01、任意周六日：`is_trading_day=false`；调休上班日为 true（以所灌日历为准，汇报抽查 3 个日期）。
2. 录入打开默认是当天；月历可一次跳到 2024-03，不必连点上一月。
3. 非交易日在录入选择器里点不了。
4. 图表近 20 交易日的 from 跳过节假日。
5. 暗色月历正常。

**完成后**：停止等待验收。清理只在人工「T-34 验收通过」后按 WORKFLOW 执行。

### T-35 · 核心指标条区间均值

**目标**：策略回顾顶部指标条：封板率、炸板率增加「当前图表区间 + 当前勾选策略」的加权均值，与今日值对照。

**范围边界**
- 允许修改：frontend TodayStats 与 MetricsChart 传参；如需聚合可在现有 GET /api/metrics 客户端计算
- 禁止修改：strategy_metrics 存库字段；登录；交易日历数据
- 禁止操作：不得对每日封板率再做算术平均；分母必须是摸板总数（T-31）

**关键约束**
1. 窗口 = 图表当前 from/to；对象 = 当前勾选的策略（与小图一致）。未勾选时不展示均值或展示空。
2. 区间封板率 = sum(limit_up_count) / sum(limit_up_count + failed_limit_count)；炸板率同理摸板分母。摸板合计为 0 则均值为 0。
3. 今日格仍显示今日（自然日当天）聚合值；封板/炸板格同时展示今日与区间均值（例如「今日 42% · 均值 38%」）。命中数/涨停数可继续对比上一交易日（上一交易日走 T-34 日历）。
4. 切换图表区间或勾选策略，均值跟着变。

**验收标准（逐条自检并汇报）**
1. 只勾选一策略、区间内涨停合计 2、炸板合计 3 → 均值封板 40%、炸板 60%。
2. 改 from/to 或勾选集合，数字变化。
3. 与图表小图同一数据源，无新 API 也可。
4. 暗色正常。

**完成后**：停止等待验收。清理只在人工「T-35 验收通过」后按 WORKFLOW 执行。
