# 04 · 编码与协作约定

> 最后更新：2026-11-16 ｜ 本文件是规则与流程的唯一来源。

## 编码规范
- 后端分层：handler / service / repository
- 前端目录：src/pages, src/components, src/api
- 不写单元测试，阶段内以本地 curl / 页面手动验证为准
- 全站界面文案统一使用「交易策略」，禁止残留「板块」；代码标识符禁止残留 sector
- 命名、目录结构变更属于约定变更，需在本文件更新并在 changelog 记录

## 阶段开始前
1. 读取 AGENTS.md 的文档索引。
2. 按需读取：每次必读 01、04、05；涉及数据读 02；涉及接口读 03；追加记录读 06。
3. 只执行 05 中第一个未完成且非 PAUSED 的阶段。

## 阶段结束固定动作（必须全部执行）
1. 按该阶段给出的验收标准自检，逐条确认。
2. 更新 05-roadmap.md：将该阶段状态改为 done；若阶段内容较多，压缩为一行并注明「细节见 changelog」。
3. 在 06-changelog.md 追加一条记录，格式：
   `YYYY-MM-DD ｜ 阶段X：名称 ｜ 新增/修改文件清单 ｜ 验收结果 ｜ 已知问题`
4. 若阶段涉及数据结构或接口变更，同步更新 02 或 03，并在 changelog 标注「契约变更」。
5. 提交代码到仓库：
      git add -A
      git commit -m "feat: 阶段X <阶段名>"
      git push
   不打 tag。若执行环境无推送权限，降级为只执行 `git add -A && git commit`，并在汇报中明确说明「已本地提交，未推送」。
6. 汇报：验收结果、changelog 条目、commit hash（与推送状态）。

## 执行纪律
- 一次只执行一个阶段，完成后停止，等待下一条指令。
- 不修改锁定项（01 的技术栈、02 的「已确认」字段、03 的「已实现」接口），确需变更时先说明理由并征得确认。
- 不在同一个任务里混合多个阶段。

## 文档维护规则
- 单一事实来源：任何信息只在一个文件定义，其他文件引用不复制。
- AGENTS.md 保持短小，只做索引与核心规则；新增细节写入对应子文件。
- 06-changelog.md 超过约 300 行时，按年归档到 docs/archive/changelog-YYYY.md，主文件保留当年记录。
- 07-todos.md 中的事项一旦确认要做，移入 05-roadmap.md 成为阶段，并从 todos 中删除，避免两处重复。
- 新增文档文件时，必须同步更新 AGENTS.md 的文档索引表。
